The Night of the Raster Beam

Inside the Commodore 64 lives Pixel, a sprite that has hung in the same spot for years. Tonight the Raster Beam, the beam that draws the screen from top to bottom 50 times a second, starts to stutter. If it stops, everything in memory disappears, Pixel included.

At 07:00 someone will pull the plug. To still exist after that, Pixel has to write its name to the floppy disk, the only place that survives the power cut. Every hour of the night is a chapter, from the top of the screen to the deepest layers of memory.

  1. 23:00 Boot
  2. 01:00 The Glitch
  3. 03:00 The Border
  4. 04:30 The Memory
  5. 06:00 The Raster Beam
  6. 07:00 The Disk

The night is not over yet: chapters are added one release at a time. Where the game is now is on the GitHub page.

Under the hood

  • Pure 6502 assembly. Assembled with ACME, no BASIC, no C, no engine. The whole game fits below $4000, and every line of the source has a comment.
  • Raster timing. Everything runs in step with the beam: the raster bars, the plasma and the parallax scroll bands change colour and scroll while the VIC-II draws those lines. The bars pump on the kick drum.
  • Sprites and a RAM character set. Ship and enemies are hardware sprites with 9-bit X positions, the starfield scrolls in a character set in RAM.
  • SID music and sound effects from WebSidTracker, a SID tracker that runs in the browser, made for this game. The tune is a tracker project: open the tracker, load raster-rumble.json and change it.
  • Real hardware. The .prg runs on a Kung Fu Flash, an Ultimate 64 or any emulator, and the .d64 is a disk image.
